Header Validation Basic Usage

(This section assumes you have read the section What is Coraza? )

  • Header validation checks the request headers listed below for valid syntax and length. Request headers not listed there are not validated.
  • By default, header validation is active in mode BLOCK: a request with at least one invalid header is rejected with status code 403. In mode DETECT, such requests are logged but not blocked.
  • Header validation does not depend on CRS, it is also active on routes where CRS is disabled. It is only inactive where the Coraza filter is disabled (spec.coraza.enabled or spec.routes[].coraza.enabled).
  • Header validation settings are at spec.coraza.headerValidation in the API Reference . They apply to all routes.

What is validated

Each validated header is checked in two ways:

  • Length: the value must not exceed the maximum length listed for the header.
  • Syntax: the value must match the grammar defined by the specification of the header, for most headers an RFC (e.g. RFC 9110 for the common HTTP headers). For widely used headers without a specification (e.g. X-Forwarded-For), the grammar follows common implementation practice.

The syntax check validates the form of a value, not its meaning. A value that is well-formed but makes no sense is accepted:

Value Result Why
Accept-Encoding: foozip accepted any token is a valid content coding, the value is not checked against known codings
Authorization: Token abc accepted Token is a valid authentication scheme name
Accept: text/ rejected the media subtype is missing
Accept: (text)/html rejected ( is not allowed in a media type

Excluding headers

If legitimate clients send headers that fail the validation, these can be excluded via spec.coraza.headerValidation.exceptions (header names are case-insensitive):

  • <header> excludes the header from both length and syntax validation
  • <header>/length excludes only the length validation
  • <header>/syntax excludes only the syntax validation
spec:
  [...]
  coraza:
    headerValidation:
      exceptions:
        - "authorization/length"
        - "x-legacy-client"

Introducing header validation

To introduce header validation without blocking legitimate traffic, it is recommended to first use mode DETECT, add exceptions for headers legitimately reported as invalid, and then switch to mode BLOCK:

spec:
  [...]
  coraza:
    headerValidation:
      mode: DETECT

To disable header validation completely, set spec.coraza.headerValidation.enabled to false.
